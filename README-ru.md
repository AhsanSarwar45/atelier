## Зачем

Claude Code и Codex хорошо делают саму работу и плохо — всё, что вокруг неё.
Запустите три таких агента в трёх терминалах, и вы не увидите, какой из них
ждёт вас, что каждый изменил и проверял ли кто-нибудь того, кто говорит, что
закончил.

Atelier запускает их за вас. Каждый чат — вкладка, которую можно закрыть и
открыть снова. Работа в нём ведётся как задача: агент заранее говорит, что
сделает, а в конце — что сделал и откуда это знает. В вашу рабочую ветку ничего
не попадает, пока вы сами не сделаете merge.

Atelier управляет агентом, которого вы уже установили и в котором вошли в
аккаунт. API-ключ добавлять не нужно, и за модель мы ничего не берём.

## Возможности

- **Чат с агентами** — Claude Code, Codex CLI и локальные модели через Goose.
  Чаты переживают закрытый браузер, а начатые в терминале тоже подхватываются
- **Задачи** — у каждого проекта есть вкладка Tasks, а каждый чат держит свои
  задачи. У задачи есть тип (bug, feature, UI change, optimization и другие),
  план, который даётся при создании, и результат, который даётся при
  завершении. Результат должен покрывать план, а задачи с кодом должны называть
  существующие коммиты. Наберите `@task` в поле ввода, чтобы попросить задачу,
  или `@task:N`, чтобы сослаться на неё. Агенты создают, начинают, блокируют и
  завершают задачи через `atelier task`. Подробнее:
  [docs/tasks.md](docs/tasks.md)
- **Визуальное доказательство** — скриншоты настоящего браузера или настоящего
  окна, до и после, снятые агентом и показанные в переписке
- **Файлы и терминал** — редактор и настоящая оболочка, которые живут дольше
  страницы
- **Аккаунты** — несколько входов у провайдеров одновременно, у каждого свой
  расход по плану и свои траты
- **MCP и плагины** — каталог, добавление серверов, управление расширениями
  Claude, редактирование skills, hooks и файлов агентов в Settings
- **11 тем**, и приложение открывается на телефоне

## Технологии

- **Frontend**: Next.js 14, React 18, TypeScript, Tailwind CSS, Radix UI, dnd-kit
- **Backend**: Rust (Axum), SQLite
- **Агенты**: Claude Code, Codex CLI и Goose через Agent Client Protocol
- **Сборка**: Статический экспорт, встроенный в Rust-бинарник через rust-embed

## Установка

Три команды, и больше ничего:

```bash
brew install AhsanSarwar45/atelier/atelier   # поставить на этот компьютер
atelier service install                      # пусть компьютер держит его запущенным
cd my-project && atelier init                # сделать папку проектом Atelier
```

Первые две — один раз на компьютер. Третья — один раз на проект.

### Требования

- [Git](https://git-scm.com/) — через него Atelier читает и пишет ваш проект
- Claude Code или Codex CLI, установленные и с выполненным входом, для чата

Чат, протоколы провайдеров, задачи, hooks и настройка проектов работают внутри
бинарника Atelier. Python, Node.js и npm не нужны для запуска и не входят в
архивы релиза.

Ничего из этого не обязано быть в PATH. Atelier сначала смотрит туда, потом в
обычные места, куда пишут установщики: `~/.cargo/bin`, `~/.local/bin`, папку
Homebrew, `/usr/local/bin`, `/usr/bin` и `/bin`, а на Windows — в обычные папки
программ пользователя и в `System32`. Поэтому их находит и копия, которую
компьютер запускает при входе: служба не наследует оболочку, а значит, и PATH.
Провайдер, установленный через менеджер версий, находится, если его называет
ваш собственный PATH; его точный путь также можно сохранить в
Settings → Dependencies.

`atelier tools` печатает каждую зависимость: есть ли она и где. Так нехватку
видно сразу, а не угадывается по экрану, который не работает.

### Homebrew (macOS / Linux)

Одна команда:

```bash
brew install AhsanSarwar45/atelier/atelier
```

Обновление: `brew upgrade atelier`.

На Windows возьмите архив из таблицы ниже, распакуйте его и положите программу в любую папку из PATH.

### Скачать

Скачайте архив для вашей платформы со страницы [GitHub Releases](https://github.com/AhsanSarwar45/atelier/releases/latest):

| Платформа | Файл |
|----------|------|
| Windows x64 | `atelier-win-x64.tar.gz` |
| macOS Apple Silicon | `atelier-darwin-arm64.tar.gz` |

В каждом архиве одна программа Atelier. К каждому релизу также прилагается

### Запуск

Одна команда поднимает всё — экраны, задачи и чат — и открывает Atelier в
браузере:

```bash
# macOS/Linux — распакуйте, затем запустите
tar -xzf atelier-darwin-arm64.tar.gz
./atelier run

# Windows
tar -xzf atelier-win-x64.tar.gz
atelier.exe run
```

Больше ничего запускать не нужно: экраны, драйверы чата, hooks и задачи
встроены в программу. Установленному приложению не нужны Rust, Python, Node.js
и npm.

| Команда | Что делает |
|---------|------------|
| `atelier run` | Запускает сервис чата и открывает Atelier в браузере |
| `atelier run --no-browser` | То же, но без браузера |
| `atelier` | То же, что `run --no-browser` |
| `atelier init [folder]` | Делает папку (по умолчанию текущую) проектом |
| `atelier task <command>` | Создаёт, начинает и завершает задачи из чата |
| `atelier service install` | Запускать при входе в систему и держать запущенным |
| `atelier service uninstall` | Больше не запускать и ничего после себя не оставить |
| `atelier service status` | Сказать, запускает ли его этот компьютер |
| `atelier remote install` | Настроить доступ к этому компьютеру издалека |
| `atelier remote` | Сказать, на каком шаге эта настройка |
| `atelier --data-dir` | Напечатать, где хранятся данные Atelier |
| `atelier --version` | Напечатать версию сборки |
| `atelier --help` | Показать этот список |

Он работает на http://localhost:3008, если `ATELIER_PORT` не задаёт другой
порт, а `ATELIER_DATA_DIR` меняет место хранения данных. Кто может к нему
подключаться — это настройка в Settings › Remote access.

### Открыть на телефоне

По умолчанию он отвечает всем в вашей сети, поэтому Atelier открывается на
телефоне, планшете или другом компьютере. При запуске он печатает, где его
открыть:

```
Atelier is running.
  On this computer   http://localhost:3008
  On your network    http://nobara.local:3008   — phone, tablet, another computer
  If that name is not found   http://192.168.1.11:3008   — this number changes when the router hands out a new one
```

Наберите имя на телефоне. Это собственное имя вашего компьютера, и оно
продолжает работать, когда роутер выдаёт другой номер, — поэтому номер стоит
под ним, а не над ним. macOS, Windows и Linux с avahi уже отвечают на это имя;
ничего дополнительно не устанавливается и не публикуется. Если браузер
телефона не находит имя (так бывает на некоторых Android), наберите номер.

Если не отвечает вообще ничего, порт закрыт файрволом вашего компьютера —
откройте 3008 или тот порт, который вы задали.

Чтобы оставить его только для этого компьютера, задайте **Answer on** равным
`127.0.0.1` в Settings › Remote access; тогда он так и скажет, а не будет
предлагать адрес, который не ответит.

### Открыть откуда угодно

Не из своей сети, а из кафе или поезда. Это другой вопрос: у Atelier нет
пароля, а порт, открытый в интернет, — это отданная машина. [Доступ к Atelier
извне вашей сети](docs/remote-access.md) объясняет, что делать вместо этого и
чего не делать никогда. Коротко: один раз запустите `atelier remote install`,
затем включите **Reach it from anywhere** в Settings › Remote access. Это ставит
перед Atelier частную сеть, а тот же раздел закрывает порт за ней и называет
адрес, который нужно открыть.

### Спросить у запущенной копии, где она

```bash
atelier where
```

Печатает те же адреса и говорит, отвечает ли что-нибудь на этом порту.
Полезно, когда его запускает сам компьютер: тогда строк, которые он напечатал,
никто не видит. Ничего не запускает.

### Запускать вместе с компьютером

```bash
atelier service install
```

Регистрирует пользовательскую службу systemd на Linux, launch agent на macOS и
задачу при входе на Windows — каждая запускает `atelier run --no-browser`,
чтобы при входе не открывалось окно. Значения `ATELIER_PORT` и
`ATELIER_DATA_DIR` на момент установки записываются в регистрацию, потому что
служба не наследует оболочку. Настройки читаются оттуда, где они хранятся,
поэтому служба подхватывает изменение, сделанное на экране, при следующем
запуске.

`atelier service uninstall` останавливает его и удаляет регистрацию.

### Настроить проект

```bash
cd my-project
atelier init
```

Команда спрашивает две вещи: имя проекта и хранить ли его общие настройки в
`.atelier/project.toml` внутри репозитория. Если ответить «нет», они остаются в
папке данных Atelier, и в проект ничего не пишется. `atelier init --name=NAME`
пропускает первый вопрос; `--repository-config` или `--personal-config` —
второй. Если запустить её на проекте, настроенном старой версией, она также
убирает hooks, которые та версия туда прописала.

У каждого проекта есть чат и вкладка Tasks. Чат, запущенный Atelier, получает
skill `atelier` — для виджетов и визуального доказательства — и skill `tasks`.
Агенты работают в той папке или worktree, где вы открыли чат. Они не создают
своих worktree или веток и не делают merge. Merge — ваше дело.

## Разработка

Требования для разработки: Node.js 22.6+ для сборки веб-части, Git и
[Rust toolchain](https://rustup.rs/).

```bash
git clone https://github.com/AhsanSarwar45/atelier.git
cd beads-web
npm install
```

Есть два сценария: **режим разработки** (frontend с горячей перезагрузкой) и **сборка из исходников** (готовый бинарник).

### Живой предпросмотр (поверх уже запущенного экземпляра)

Если Atelier уже работает с вашими настоящими проектами — установленная служба
на :3008, — одна команда показывает экраны из этого клона поверх её данных:

```bash
npm run dev:live       # http://127.0.0.1:3007, данные из Atelier на :3008
```

Ничего не собирается, не устанавливается и не перезапускается: изменение в
этом клоне видно после обновления страницы. `BEADS_BOARD_URL` направляет его на
Atelier в другом месте, `PORT` — на второй предпросмотр (например, из worktree).
Он не запускается, если там не отвечает Atelier: предпросмотр без данных
выглядит как сломанное приложение.

### Режим разработки (горячая перезагрузка frontend)

Dev-сервер Next.js (порт 3007) отдаёт frontend с горячей перезагрузкой; бэкенд на Rust (порт 3008) отдаёт API. Они общаются между собой через CORS — на бэкенде он открыт.

1. **Укажите frontend адрес бэкенда:**

   ```bash
   cp .env.local.example .env.local   # задаёт NEXT_PUBLIC_BACKEND_URL=http://localhost:3008
   ```

2. **Сначала соберите папку `out/`** (пока `output: 'export'` ещё включён). Сервер на Rust встраивает `out/` через rust-embed, поэтому она должна существовать до сборки бэкенда:

   ```bash
   npm run build
   ```

3. **Только после этого** закомментируйте `output: 'export'` в `next.config.js` — `next dev` несовместим со статическим экспортом.

4. **Запустите оба сервера** в разных терминалах:

   ```bash
   npm run dev              # Терминал 1 — frontend на http://localhost:3007
   npm run server:dev       # Терминал 2 — бэкенд/API
   ```

5. Откройте **http://localhost:3007**. Правки frontend перезагружаются на лету; запросы к API уходят на бэкенд на порт 3008.

> Шаг с `.env.local` / `NEXT_PUBLIC_BACKEND_URL` нужен **только для разработки**. Для сборки готового бинарника уберите его (или оставьте переменную незаданной) — там frontend и бэкенд работают на одном адресе.

### Сборка из исходников (готовый бинарник)

Собирает тот же самодостаточный бинарник, что публикует CI в [Releases](https://github.com/AhsanSarwar45/atelier/releases/latest). Frontend и все сервисы времени выполнения встроены в него.

```bash
npm install
# оставьте `output: 'export'` включённым в next.config.js (это значение по умолчанию)
npm run build                 # статический экспорт → out/
cd server
cargo build --release         # бинарник → server/target/release/atelier (.exe на Windows)
```

С Nix флейк собирает и запускает тот же бинарник без клона репозитория:

```bash
nix run github:AhsanSarwar45/atelier
```

Запустите бинарник и откройте **http://localhost:3008**:

```bash
./server/target/release/atelier
```

## FAQ

**В: Нужен ли API-ключ?**
О: Нет. Atelier запускает `claude` или `codex`, которые вы уже установили и в
которых вошли, так что работа идёт по вашему собственному плану. Atelier ничего
не берёт сверху.

**В: Как добавить проект?**
О: Запустите `atelier init` в папке проекта или нажмите "Add Project" на
дашборде и выберите папку.

## Происхождение

Atelier начинался как форк
[Beads-Kanban-UI](https://github.com/AvivK5498/Beads-Kanban-UI) от Aviv Kaplan —
канбан-доски для Beads CLI. От той формы ничего не осталось: доски и Beads
больше нет, а работа ведётся в собственных задачах Atelier. Полная история с
обоснованиями: [docs/changelog.md](docs/changelog.md).
